# Быстрый экспериментальный анализатор

Скорость улучшена, качество обнаружения нарушений ещё не подтверждено.
Это исследовательская версия одной категории, не готовое решение всего кейса.

## Как устроен

1. Из человеческой разметки получены 67 вырезок объектов из четырёх train-видео.
2. Банкноты, документы, сейф/хранилище и инкассаторская сумка — разные классы.
   Сумки X-15 выделены отдельным классом по явному уточнению команды;
   исходный файл ручной разметки не перезаписан.
3. DINOv2-Small извлекает признаки локально на CPU, поверх обучен взвешенный
   ridge-классификатор. Его оценки не являются вероятностями.
4. Положения кандидатов рассчитаны по train-прямоугольникам. Это предположение
   о сходном положении камеры; автоматический поиск объектов на любом ракурсе
   пока не реализован.
5. Qwen3-VL-4B оценивает присутствие персонала у рабочего места, без распознавания
   лиц/личности. Ответ привязан к явным ID кадров; пропущенный ID — «неясно».
6. Два последовательных кадра с банкнотами и отсутствием сотрудника дают
   кандидат события. Этот узкий признак не покрывает оставленные деньги
   при продолжающемся присутствии сотрудника/следующем обслуживании.

Внешних вызовов при инференсе нет. ONNX Runtime работает с локальным файлом
на CPU, телеметрия отключается перед созданием сессии. Запуск DINO-эксперимента
успешно выполнен без сетевого доступа в sandbox.

## Скорость и диагностические результаты

- Извлечение признаков 67 вырезок: Qwen vision — 13,328 с,
  DINOv2 — 2,519 с. Это скорость компонента, не полного видео.
- Первоначальный DINO crop-пилот: 46 вырезок X-5 для обучения,
  21 вырезка других источников для диагностики, 12/21 правильных ответов.
  Документов в отложенных источниках нет, их обобщение не проверено.
- После разделения типов сумки/хранилища внутренний diagnostic X-27:
  5/6 правильных классов, 6/6 «банкноты / другое». Это шесть зависимых вырезок
  одного train-ролика, использованных при разработке. Это не 83%/100% качества
  нарушений и не независимый финальный тест.
- Итоговый объектный классификатор после диагностики обучен на всех
  67 train-вырезках; validation-видео в обучении не участвовали.
- Fast train v1: X-5/X-26/X-27 разобраны верно, 21,018–22,856 с на видео,
  ошибка времени на X-26 — 1 с. Предыдущий ROI-вариант на тех же видео
  занимал 150,803–156,923 с и ошибался на двух отрицательных роликах.
  Это сравнение обучающих пилотов, не обещание итогового качества.

## Проверочная шестёрка разработки

Меток и кадров validation нет в объектной разметке, настройках положений
и обучении классификатора. Это прежняя dev-validation, уже использованная
для диагностики предыдущих подходов, поэтому она не является независимым
финальным тестом. Нужен отдельный нетронутый источник для финального заявления.

- fast-cash-validation-v1: 3/6 ответа, три ошибки формата массива из семи
  состояний вместо восьми. Все сбои учтены в общем знаменателе.
- После исправления явных ID fast-cash-validation-v2 обработал все 6 роликов
  без сбоев за 21,946–25,865 с каждый. TP=0, TN=4, FP=0, FN=2.
  Accuracy=66,7%, recall нарушений=0%, balanced accuracy=50%.
  Это поведение «всегда нет нарушения», вариант не принят как рабочий детектор.
  Положительные X-4/X-44 не найдены; требуется проверить и локализацию
  объектов на другом ракурсе, и соответствие узкого признака разметке категории.

На X-31 кадровый классификатор оставил все состояния неопределёнными;
поиск банкнот не дал срабатываний. Отсутствие срабатывания узкого
экспериментального детектора не является доказательством отсутствия всех
нарушений кейса. Worker на эту версию автоматически не переключён.

## Воспроизведение на Mac

```bash
.venv-ml/bin/python -m pip install -r requirements-ml.txt
.venv-ml/bin/python -m ml.datasets.download_dino
.venv-ml/bin/python -m ml.evaluation.run_baseline --manifest data/processed/cash-category-v2.csv --model artifacts/models/qwen3-vl-4b-4bit --output artifacts/evaluations/fast-cash-new-run --split validation --detector fast --manual-annotations data/processed/manual-grounding-v1/annotations.json --crop-model artifacts/models/cash-crops-v1 --dino-model artifacts/models/dinov2-small-onnx
```

Выходной каталог должен быть новым. Артефакты всех неудачных и удачных
пилотов сохранены; код, настройки и хеши присутствуют рядом с результатами.

## Полный поиск по кадру: dense-v2, 18 октября

Уточнение команды сохранено отдельно: X-4/X-44 показывают именно видимые
банкноты, а не сумки. Эти положительные метки не изменены ради метрики.
Файл `data/processed/category-confirmations-v1.json` фиксирует источник уточнения.

Новый эксперимент `ml.dense_cash` просматривает весь кадр перекрывающимися
участками 224×224 без уменьшения исходных мелких объектов. Разметка banknotes,
documents, cash_storage и collection_bag даёт 388 признаков патчей, центры которых
находятся внутри человеческих прямоугольников train. Неразмеченные участки не
объявлены фоном. Использовано 56 train-кадров четырёх источников, без validation.
Проверка этапа операции расширена: завершение взаимодействия, переключение
на следующего клиента или уход сотрудника; пауза сама по себе не считается концом.

Высокое разрешение целого изображения непосредственно в этот ONNX-экспорт
не поддерживается (позиционные embeddings 257 против 1981). Поэтому используется
нативная сетка отдельных участков; неудачная попытка не считается обученной моделью.

Результаты `artifacts/evaluations/dense-validation-v2/score/metrics.json`:

| Видео | Метка | Ответ эксперимента |
|---|---:|---|
| X-4 | 1 | 1 |
| X-23 | 0 | Неопределённо |
| X-31 | 0 | 0 |
| X-37 | 0 | Неопределённо |
| X-43 | 0 | 0 |
| X-44 | 1 | 0 |

- Время 22,202–26,439 с/видео; все шесть обработаны без сбоев исполнения.
- TP=1, TN=2, FP=0, FN=1, два неопределённых отрицательных случая.
- Accuracy по всем шести = 50%; recall положительных = 50%; coverage = 66,7%.
- 75% среди четырёх определённых ответов не является общей accuracy.
- Precision 100% основана только на одном срабатывании и не подтверждает надёжность.
- Ошибка времени единственного найденного события = 7 с относительно текущей метки;
  спорное время дубликата X-4/X-47 остаётся отдельной проблемой исходных данных.
- В train-пилоте X-5/X-26/X-27: один неверный положительный ответ и два
  неопределённых. Пилот не подтверждает качество обобщения.
- Поиск cash срабатывал на всех восьми выбранных кадрах каждого из шести
  проверочных видео. Это признак слишком широкого срабатывания компонента,
  а не доказательство наличия денег на каждом кадре. Отдельной оценки локализации
  на validation пока нет; автоматическое подтверждение нарушения недопустимо.

**Решение:** эксперимент не принят для backend. Старый быстрый occupancy-вариант
тоже не принят. Ускорение измерено, необходимое качество ещё не получено.
Следующий приоритет — явная train-разметка похожих на деньги документов/предметов,
отрицательных областей и границ этапов операции, а не дополнительные случайные
загрузки датасетов или подгонка порогов по этой же проверочной шестёрке.

Для воспроизведения нового эксперимента:

```bash
.venv-ml/bin/python -m ml.evaluation.train_dense_cash --annotations data/processed/manual-grounding-v1/annotations.json --review-root artifacts/grounding-review-v1 --corrections data/processed/category-corrections-v1.json --model artifacts/models/dinov2-small-onnx --output artifacts/models/dense-cash-new
.venv-ml/bin/python -m ml.evaluation.run_baseline --manifest data/processed/cash-category-v2.csv --model artifacts/models/qwen3-vl-4b-4bit --output artifacts/evaluations/dense-new --split validation --detector dense --manual-annotations data/processed/manual-grounding-v1/annotations.json --crop-model artifacts/models/dense-cash-new --dino-model artifacts/models/dinov2-small-onnx
.venv-ml/bin/python -m ml.evaluation.score --manifest data/processed/cash-category-v2.csv --predictions artifacts/evaluations/dense-new/predictions.jsonl --split validation --output artifacts/evaluations/dense-new/score
```

Новый алгоритм и предыдущие версии не перезаписывают исходные метки и результаты.
Worker/API окружения разделены; 13 backend-тестов прошли также в Python 3.12
ML-окружения. 17 тестов разметки, метрик, парсеров и покрытия кадра прошли;
Ruff E4/E7/E9/F/I для новых файлов прошёл. Это проверки кода, не метрики ML.
