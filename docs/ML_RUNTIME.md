# Текущий локальный ML runtime

Выбран `ANALYZER_PATH=ml.temporal_inference:analyze`: CPU-анализатор DINOv2
с обученными temporal RBF kernel-ridge event-heads. Qwen, MLX и GPU не нужны.

## Запуск

Установить `requirements-runtime.txt` в Python 3.12. Разместить:

- `artifacts/models/dinov2-small-onnx/model.onnx`
- `artifacts/models/dinov2-small-onnx/preprocessor_config.json`
- `artifacts/models/temporal-events-review-v3/model.npz`

Указать анализатор в `.env`, остановить старый worker, запустить один
`python -m backend.worker`. На текущем Mac используется
`.venv-ml/bin/python -m backend.worker`. API/UI работают в основном окружении.
Интерфейс: http://127.0.0.1:8502.

## Вход и результат

Runtime получает только видео. Нет поиска по имени, X-ID, хешу или таблице
ответов. Визуальные признаки последовательности кадров поступают обученным
головам; нормативные ссылки добавляются из `ml/rules.py`. Таймкоды предварительные,
кадры извлекает backend из исходной записи. Для инференса не нужны train-данные.

## Ограничения

Классификатор выдаёт решение для успешно декодированного видео вместо прежнего
языкового `analysis_uncertain`. Это не гарантия правильности. Повреждённые файлы,
недостающие ресурсы и превышение времени остаются ошибками, без подмены
отрицательным вердиктом.

18 категорий включают наблюдения без установленного прямого запрета в двух
документах. Для них указываются событие для проверки и ближайший нормативный
контекст, а не утверждение юридической виновности.

Предыдущий cash-only анализатор и Qwen/LoRA-эксперименты сохранены для разработки
и не являются текущей конфигурацией worker.
