# Backend Forte DVG

FastAPI принимает MOV/MP4, сохраняет задание в SQLite и возвращает `job_id`.
Отдельный worker выполняет локальный анализ и сохраняет результат с исходными
JPEG-кадрами. Текущий анализатор — `ml.temporal_inference:analyze`; модели,
артефакты и границы качества описаны в [ML_RUNTIME.md](ML_RUNTIME.md).

Основной вариант запуска — **два процесса**: единый сервер сайта/API на порту
9000 и один worker. Отдельный API на 8000 для этого варианта не требуется.

## Подготовка

Нужны Python 3.12 и локальные веса. Все команды выполняются из корня проекта,
где находятся `backend/`, `frontend/`, `ml/` и `requirements-runtime.txt`.
Для существующего окружения пропустите его создание.

macOS / Linux:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-runtime.txt
```

Windows PowerShell, если `python --version` показывает Python 3.12:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-runtime.txt
```

Активация окружения не нужна: далее используется полный путь к его Python.
В командах ниже для Windows заменяйте `.venv/bin/python` на
`.\.venv\Scripts\python.exe`. Полный прогон на Windows пока не подтверждён.

Разместите локальные артефакты:

```text
artifacts/models/dinov2-small-onnx/model.onnx
artifacts/models/dinov2-small-onnx/preprocessor_config.json
artifacts/models/temporal-events-review-v3/model.npz
```

Веса не входят в Git. Для инференса не требуются обучающие видео, Excel,
ручные рамки или train-manifest. Текущий runtime использует CPU/ONNX Runtime;
MLX и GPU не нужны.

Создайте `.env` из `.env.example` **только если своего файла ещё нет**. В
существующий `.env` добавляйте недостающие настройки вручную. Сгенерируйте ключ:

```bash
.venv/bin/python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Минимальные настройки:

```dotenv
API_KEY=replace-with-your-generated-key
ANALYZER_PATH=ml.temporal_inference:analyze
STORAGE_ROOT=data/runtime
JOB_TIMEOUT_SEC=270
MAX_UPLOAD_MB=100
MAX_PENDING_JOBS=8
```

Вставьте сгенерированное значение в `API_KEY`; оно должно содержать не менее
24 символов. Не публикуйте ключ и `.env`. Один сервер и worker должны читать
одинаковые настройки и использовать одну локальную папку `STORAGE_ROOT`.

## Основной запуск: сайт и API вместе

Терминал 1:

```bash
.venv/bin/python -m uvicorn backend.public:app --host 127.0.0.1 --port 9000
```

Терминал 2:

```bash
.venv/bin/python -m backend.worker
```

- Сайт: http://127.0.0.1:9000
- Swagger: http://127.0.0.1:9000/docs
- Проверка доступности API: http://127.0.0.1:9000/health

Оставьте оба процесса работающими. `backend.public:app` обслуживает сайт и API
на одном адресе. Сервер интерфейса передаёт запросы собственному API на 9000;
остановка отдельного development API на 8000 на этот вариант не влияет.
Ключ подставляется сервером интерфейса и не передаётся браузеру в JavaScript.

Перед сменой модели остановите worker через Ctrl+C и запустите его заново.
Не запускайте одновременно worker с разными анализаторами для одной очереди.
При изменении порта сервера задайте тот же `PUBLIC_PORT` в окружении либо
настройте `PUBLIC_INTERNAL_API_URL` на фактический локальный адрес API.

### Временный публичный доступ

Локальный адрес `127.0.0.1` доступен только на компьютере сервера. Для
демонстрации уже использовался Cloudflare Tunnel к единому серверу на 9000.
При установленном `cloudflared` он запускается отдельным процессом:

```bash
cloudflared tunnel --url http://127.0.0.1:9000
```

Используйте HTTPS-адрес, выданный туннелем: сайт находится в `/`, документация —
в `/docs`, API — в `/api/v1/`. Это временный адрес, а не постоянный хостинг.
Компьютер, интернет, сервер, worker и туннель должны продолжать работать;
при создании нового временного туннеля адрес может измениться.

Для постоянного размещения нужны постоянно работающий сервер, согласованное
хранение видео и весов, HTTPS/reverse proxy, ограничения размера запроса и
управление процессами. Публичная доступность сама по себе не подтверждает
готовность к промышленной эксплуатации. Передавайте ключ проверяющим отдельно.

## Дополнительный режим разработки

Если UI и API нужно запускать независимо, вместо единого сервера используйте
три терминала:

```bash
# API на 8000; автоматическая перезагрузка только backend
.venv/bin/python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 --reload --reload-dir backend
```

```bash
# Один worker
.venv/bin/python -m backend.worker
```

```bash
# UI на 8502
.venv/bin/python -m frontend.app
```

Сайт: http://127.0.0.1:8502, Swagger: http://127.0.0.1:8000/docs.
Самостоятельный UI использует `BACKEND_URL` (по умолчанию
`http://127.0.0.1:8000`). Этот режим не нужен для единого публичного входа.

## API и проверка через Swagger

Откройте `/docs` на выбранном сервере. Нажмите **Authorize** и вставьте только
значение ключа, без `API_KEY=` и без `Bearer`.

1. `POST /api/v1/analyze` → **Try it out** → выберите MOV/MP4 в поле `file` →
   **Execute**. Заголовок авторизации — `X-API-Key`.
2. Ответ HTTP 202 содержит `job_id` и `status: processing`.
3. Подставьте идентификатор в `GET /api/v1/jobs/{job_id}` с тем же ключом.
   Повторяйте запрос до `done` или `failed`.

При `done` ответ содержит `verdict` (`violation` / `no_violation`) и
`violations`. Для каждого события возвращаются тип, время, описание,
нормативные поля и 1–3 JPEG в `image_base64` с `timestamp_sec`.
При `no_violation` список событий пуст. При `failed` возвращается `error`;
техническая ошибка не превращается в отрицательный вердикт.

Без worker задание остаётся `processing` до таймаута. Публичный `/health`
показывает только доступность API, а не готовность модели или worker.
Полный контракт: [../contracts/api.md](../contracts/api.md).

## Контракт модели

Локальная функция анализатора:

```python
analyze(video_path: pathlib.Path) -> list[Candidate]
```

Путь задаётся в `ANALYZER_PATH` в формате `module:function`. Схема `Candidate`
находится в `backend/app/domain/schemas.py`, протокол — в
`backend/app/ports/analyzer.py`.

Для каждого события нужны `type`, `timecode_sec`, `description`, `rule`,
`source_title`, `source_url`, необязательный `source_section` и
`evidence_timestamps` (1–3 времени). Pipeline извлекает реальные кадры из
исходного видео и кодирует их в JPEG/base64. Пустой список означает успешно
завершённый анализ без найденных событий; ошибки должны вызывать исключение.

Тестовые анализаторы из `tests.analyzers` предназначены только для синтетических
тестов. Runtime модели работает без внешних AI API; нормативные ссылки берутся
из подготовленного реестра. Кадры и описания не должны отправляться в облачный
AI-сервис. Публичный HTTPS-вход обеспечивает транспорт к локальному серверу и
не меняет место исполнения модели.

## Хранение и ограничения

- По умолчанию: база `data/runtime/jobs.sqlite3`, видео —
  `data/runtime/uploads/<uuid>.mov` или `<uuid>.mp4`. Относительный
  `STORAGE_ROOT` считается от корня проекта.
- SQLite-очередь предназначена для процессов на одном сервере. Выбор следующего
  задания атомарный; внутренние `queued`/`running` отображаются как `processing`.
- Таймаут — 270 секунд от принятия задания, включая ожидание в очереди.
  Дочерний процесс останавливается при превышении времени. Просроченные задания
  получают `failed`, в том числе после перезапуска worker.
- По умолчанию: 100 МиБ на файл и 8 незавершённых заданий. Переполнение очереди
  возвращает HTTP 429, превышение размера — 413, неподдерживаемое расширение —
  415. Пустой файл возвращает 400; проверка декодирования выполняется в worker.
- Один worker обрабатывает одно видео за раз. Модель загружается в дочернем
  процессе каждого задания. Ограничение времени не является гарантией
  точности или времени обработки на другом оборудовании.
- Незавершённая или отклонённая загрузка очищается. Автоудаление сохранённых
  видео и результатов пока не реализовано; перед эксплуатацией необходимы
  согласованный срок хранения и очистка.
- Извлечение кадров использует FPS. Для переменного FPS нужна отдельная проверка
  соответствия времени; точность всех таймкодов независимо не подтверждена.
- Для некоторых категорий установлен только нормативный контекст. Наличие
  события в ответе не доказывает юридическое нарушение; подробности — в
  [NORMATIVE_MAPPING.md](NORMATIVE_MAPPING.md).

## Тесты

```bash
.venv/bin/python -m unittest tests.test_backend tests.test_public -v
```

Тесты используют синтетическое видео и тестовые анализаторы. Они проверяют
авторизацию, загрузку, очистку, очередь, сохранение результата, JPEG, таймаут,
отсутствие модели и единый gateway. Это проверки программной логики, а не
независимая оценка распознавания.
