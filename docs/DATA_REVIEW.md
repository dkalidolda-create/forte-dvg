# Разбор обучающих данных

Запуск из корня проекта, в окружении с установленными requirements.txt:

```bash
python -m ml.datasets.prepare_review --labels data/raw/open_labels.xlsx --videos data/raw/videos --output data/processed/review-v1
```

Откройте data/processed/review-v1/index.html локально в браузере.
Воспроизведение .mov зависит от кодека и браузера: при необходимости смотрите
исходный ролик в локальном видеоплеере. HTML показывает только выборку кадров.
Если исходные файлы перенесены, ссылки на видео нужно пересоздать.
Скрипт никогда не перезаписывает существующий каталог, чтобы сохранить разметку.

## Результаты

- manifest.csv — сопоставление Excel/видео, параметры, SHA256, train/validation.
- audit.json — сводка проверок, число роликов и баланс меток.
- frames/ — локальные JPEG вокруг метки (±6 секунд), для отрицательных — обзор.
- index.html — локальная галерея для человека; внешних скриптов/ресурсов нет.
- review.csv — таблица для ручной разметки, UTF-8 BOM для Excel.

## Как заполнять review.csv

Одна строка = одно событие. Если в видео несколько событий, продублируйте строку
и заполните отдельное время, категорию и правило для каждого. Если событий нет,
зафиксируйте просмотр полного видео в notes и review_status.

1. observed_action — только наблюдаемое действие, без юридических догадок.
2. event_type — согласованное название категории, а не просто «нарушение».
3. event_start_sec / event_end_sec — границы в секундах исходного видео.
4. rule / source_title / source_url / source_section — проверенное правило и источник.
5. reviewer — кто проверил; review_status: pending / reviewed / uncertain.
6. related_scene_group — одинаковый ID для связанных дублей/съёмок одной сцены.

Исходные target и таймкод не менять. Спорные метки отмечать в notes.
Пустой норматив нельзя заменять выдуманной ссылкой. Внешние AI-сервисы не использовать.
Новые синтетические категории скрипт не создаёт, нарушений не распознаёт.

## Разделение

Seed 42, примерно 80/20 по исходным видео с балансом бинарной метки.
Байтовые дубликаты по SHA256 помещаются в одну часть.
Это предварительная валидация: связанные сцены, одинаковые действия и новые
категории ещё не проверены человеком. После разбора объедините связанные ролики
и проверьте наличие категорий в train/validation; только затем зафиксируйте split.
Не помещайте кадры одного ролика в разные части и не используйте видео жюри
для обучения или подбора порогов. Положительная метка ролика не означает, что
все его кадры положительные; отсутствие метки кадра не делает его отрицательным.

Всё содержимое data/ остаётся вне Git. Передавать материалы можно только
авторизованной команде в рамках правил хакатона. Не открывайте gallery/кадры
через облачный AI-анализатор. Код подготовки можно коммитить отдельно от данных.
