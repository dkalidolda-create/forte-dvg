# Forte DVG

Локальный прототип анализа видео кассовых операций для Datathon.
Backend и инструменты данных реализованы; ML находится в экспериментальной
стадии. Полный сценарий кейса пока не готов.

## Текущее состояние

- API принимает MOV/MP4, проверяет X-API-Key, создаёт задание и возвращает job_id.
- SQLite хранит очередь и результаты; отдельный worker обрабатывает задания
  в дочернем процессе с ограничением времени. Pipeline получает настоящие JPEG-кадры.
- Streamlit пока проверяет /health и выбирает файл. Отправка на анализ и результаты
  ещё не подключены. Зелёный /health не означает готовность модели.
- Экспериментальные модели проверяют одну категорию: банкноты остаются после операции.
  Последний dense-v2: 3 правильных ответа из 6 dev-validation видео, одна ошибка,
  два неопределённых; общая accuracy 50%, recall 50%, 22–26 с/видео после загрузки.
  Это маленькая повторно использованная выборка разработки, не финальное качество.
- Ни один ML-вариант не принят и не подключён к worker. Пустой ANALYZER_PATH даёт
  model_not_configured. Не подменять его тестовым предиктором для демонстрации качества.
- X-15 исключён из cash-категории: команда указала инкассаторскую сумку без
  видимых банкнот. X-4/X-44 остаются положительными по видимым банкнотам.

## Запуск backend и интерфейса

Клонируйте репозиторий один раз, затем откройте **папку forte-dvg** в VS Code.
Если он уже клонирован, перед git pull сохраните свои незакоммиченные изменения.

macOS:

```bash
git clone https://github.com/dkalidolda-create/forte-dvg.git
cd forte-dvg
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Windows PowerShell:

```powershell
git clone https://github.com/dkalidolda-create/forte-dvg.git
cd forte-dvg
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Скопируйте `.env.example` в `.env`, если своего `.env` ещё нет. Сгенерируйте
ключ командой `python -c "import secrets; print(secrets.token_urlsafe(32))"`
через Python созданного окружения и запишите значение в API_KEY. Свой ключ
не публиковать. ANALYZER_PATH пока оставить пустым.

В отдельных терминалах из корня проекта (используйте Python своего окружения):

```bash
python -m uvicorn backend.app.main:app --reload --reload-dir backend
python -m backend.worker
python -m streamlit run frontend/app.py
```

На macOS замените `python` на `.venv/bin/python`, на Windows —
`.\.venv\Scripts\python.exe`, если окружение не активировано.
Swagger: http://127.0.0.1:8000/docs, интерфейс: http://localhost:8501.
В Swagger нажмите Authorize и введите свой API_KEY.

## Данные и ML

В Git находятся исходники, тесты и документация. `.env`, виртуальные окружения,
видео, Excel, ручные аннотации, кадры, веса и сырые ответы моделей исключены.
После git pull они у коллег **не появятся**. Данные передаются только
авторизованной команде в рамках правил кейса и хранятся локально.

Manifest содержит абсолютные пути к видео. На другом компьютере нужно
пересоздать его для местных файлов, сохранив согласованные группы дубликатов,
разделение и исправления разметки. Не переносите случайно кадры одного видео
между train и validation. Размеченные объекты не заменяют метки этапа операции.

MLX-эксперименты используют отдельный Python 3.12 `.venv-ml` и Apple Silicon;
на Windows они не проверены. Установка зависимостей/скачивание публичных весов
требуют сети, но инференс работает локально, без облачных AI-запросов.

Нормативная привязка, подключение модели к API/UI и публичное развёртывание остаются
следующими этапами.

## Проверки

```bash
python -m unittest tests.test_backend -v
```

В ML-окружении дополнительные проверки и полный набор:

```bash
.venv-ml/bin/python -m unittest discover -s tests -t .
```

Тесты используют синтетические видео и проверяют код, парсеры и метрики.
Они не подтверждают точность распознавания реальных нарушений.
